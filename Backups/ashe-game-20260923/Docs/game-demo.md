# Game 场景战斗 Demo

状态：规则已由用户逐项确认，2026-09-22；代码及 Game 场景已接入，编译、构建、逻辑检查、Player 集成检查和离屏画面检查通过。

## 用户确认的游戏方向

游戏主体是肉鸽：玩家操控一名主角，对抗大量怪物。主角具有类似英雄联盟 / DOTA2 的技能设计，操作方式和 UI 布局参考 DOTA2。技能的具体规则尚未设计。

本轮以既有 `Assets/Scenes/Game.unity` 为主场景，使用 Unity 内置基础模型代表玩家和怪物。实现一万敌人与玩家的交互：鼠标移动，自动攻击最近敌人，并发射子弹。

本轮由「基础框架 + 独立压测」推进到「可操作的最小战斗 Demo」。保留上一轮 Benchmark10k 场景用于隔离性能比较。

## 已确认规则

1. 右键点击或按住地面移动；俯视镜头跟随、滚轮缩放；移动中可以自动攻击。
2. 一万怪物全部追逐玩家；近身按间隔造成伤害；玩家生命耗尽后失败并可重开；被击杀的怪物不补刷。
3. 在射程内自动选择最近敌人；子弹追踪指定目标，命中扣血并消失；底部状态栏和 Q/W/E/R 技能占位，本轮不实现主动技能。

确认依据：用户回复「1.对 / 2.对 / 3.对」。具体数值由实现设为可调参数，不代表最终平衡设计。

## 技术调查事实

- Game 场景保留原 Camera、Directional Light，新增 Game Demo 控制器，已追加到构建列表；不改动 Main/SelectScene 的原有启动顺序。
- 项目已配置 Unity 6000.3.18f1、URP、Entities 与 Entities Graphics。
- 输入当前使用旧 Input Manager，`activeInputHandler=0`；可在既有输入模式下接入鼠标。
- 已新增 CombatSimulationSystem、CombatDemoController、CombatHud，以及 CombatSettings / CombatPlayer / CombatEnemy / CombatProjectile 数据。Benchmark10k 保持独立。

## 运行入口

直接打开 `Assets/Scenes/Game.unity` 并 Play，或菜单 `Tools > Roguelike > Open Game Demo`。玩家为青蓝胶囊，敌人为红色方块，子弹为黄色球体。所有美术均为引擎基础模型与项目内 URP 材质。

- 右键点击/按住：设置地面目的地，场地边界内移动。
- 滚轮：拉近操作或拉远观察整个敌群。默认操作镜头不承诺一万只怪物同时在画面内，所有存活怪物持续参与模拟。
- 底部 UI：生命、射程、存活敌人、击杀、弹体、时间和 FPS；技能槽明确标记「未实现」。UI 上点击不会发送地面移动命令。
- F5：重开；死亡后也可点击「重新开始」。重开清理本次敌人、子弹和配置后重新生成，不叠加第二批怪物。
- 构建：`Tools > Roguelike > Build Windows Game Demo`，输出 `Builds/GameDemo/GameDemo.exe`，仅以 Game 为独立程序入口。

## 已实现的边界行为

- 目标离开射程后已发射的子弹继续追踪；只在开火时检查射程。
- 目标已死亡/销毁或弹体寿命耗尽时回收弹体，不自动更换目标。
- 同帧多个弹体命中同一目标不会重复计数或重复销毁；最先致死的命中计一次击杀。
- 没有目标时按攻击节奏重新索敌，避免每帧无意义全量搜索。
- 玩家死亡后停止本局战斗推进；敌人和弹体留在失败画面，重开时统一清理。
- 空旷场地无障碍寻路，敌人之间不做物理阻挡/分离，会重叠；后续避让需求另行确认。

## ECS 实现边界

敌人由 Burst IJobEntity 并行追逐并通过 NativeQueue 汇总近战伤害；每帧一次明确同步点后结算玩家生命。单玩家索敌只在开火时扫描，复杂度 O(N)，不是全体两两检测。少量追踪弹按顺序结算目标伤害，用 ECB 集中处理生成/销毁。

玩家输入、镜头、模型和 HUD 为少量 GameObject。敌人和子弹使用 Entities Graphics，共享网格和材质；不使用一万个 MonoBehaviour、Collider 或 NavMeshAgent。HUD 以 10Hz 更新文字。

## 验证

`Tools > Roguelike > Validate Combat Logic` 执行隔离 World 的战斗逻辑检查。带 `--demo-smoke --demo-output <绝对目录>` 启动独立 Player 可运行输入投影、UI 拦截、命中/击杀、死亡、重开与销毁清理的集成检查，并输出结果和截图；正常游玩不启用该探针。

结果与证据见 [Game Demo 验证记录](validation-game-demo-2026-09-22.md)。正常版入口为 `Builds/GameDemo/GameDemo.exe`，双击运行即可；测试参数只用于自动检查。功能检查不代表目标硬件的正式 60 FPS 验收。

## 验收条件

- 直接打开 Game 场景进入 Play 可以操作玩家，无需先运行压测场景。
- 一万敌人实际具有战斗数据和行为；模拟数与可见数分开记录。
- 鼠标移动、索敌、子弹、命中和击杀按确认规则形成闭环。
- UI 不应把鼠标点击透传为地面移动。
- 死亡/重开和场景退出清理按确认范围验证，不污染 Benchmark10k。
- 通过 Unity 编译与 Windows Player 功能检查，记录实际硬件、负载和未验证项；不将 Demo 功能完成等同于完整游戏性能达标。
