# Dota 风格视野系统：调研与验收设计

2026-09-22 调研，2026-09-23 更新实现状态。已确认：独立功能场景、本地双阵营可切换、完整通用视野演示、美术暂不投入。包含未探索/已探索/当前可见、阵营共享、昼夜、高低地/树木、地面/飞行视野、眼/真视、隐身、敌人信息隐藏。用户最终明确：普通敌人都不提供视野，仅给指定敌人挂“敌人视野”预制体后提供共享视野。实现与实测状态见 [演示说明](fog-of-war-demo.md)。

## 调研依据与适用边界

| 一手资料 | 结论及本项目用法 |
| --- | --- |
| [Valve Reborn 更新](https://www.dota2.com/reborn/updates/?l=english) | 自定义游戏提供 SetUnseenFogOfWarEnabled；未探索黑雾应独立于当前可见性。历史记录也涉及树木变化与迷雾刷新、雾中目标指令问题，可用于设计回归案例，不能代替当前版本完整规则。 |
| [Riot：A Story of Fog and War](https://www.riotgames.com/en/news/story-fog-and-war) | 游戏判定数据与画面分辨率分开；提高网格分辨率有平方成本。本文是历史实现经验，不把文中的 128×128 当成 Dota 或本项目规格。 |
| [Gemserk：RTS fog of war](https://blog.gemserk.com/2018/11/20/implementing-fog-of-war-for-rts-games-in-unity-2-2/) | 网格按阵营记录当前/历史状态，逻辑查询与渲染共享数据；作者指出模糊画面可能渗出高地边界，不能靠模糊后的纹理决定目标可见性。 |
| [Albert Ford：Symmetric Shadowcasting](https://www.albertford.com/shadowcasting/) | 解释格子视野、遮挡阴影和对称性，并给出非递归方式。适合对比视野算法；“对称”只适用于相同地面遮挡条件，高低地本来允许非对称。 |
| [Adam Milazzo：Roguelike Vision Algorithms](https://www.adammil.net/blog/v125_Roguelike_Vision_Algorithms.html) | 比较拐角、窄缝、墙边与柱子阴影规则；需要固定测试图，不以算法名称代替结果验收。 |
| [OpenRA Shroud 源码](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Game/Traits/Player/Shroud.cs) | 可研究探索状态与视野源维护的分工；不直接导入另一套游戏框架。源码引用或移植前另核许可证。 |
| [OpenRA Traits](https://docs.openra.net/en/release/traits/) | 高度差、移动重算阈值与视野来源是配置项，支持将逻辑配置和对象显示分离。 |
| [Entities 1.4 enableable components](https://docs.unity3d.com/Packages/com.unity.entities@1.4/manual/components-enableable-intro.html) | 启用状态避免频繁结构变化，但模拟状态和渲染剔除需分别设计；不能禁用整个隐藏敌人而停止它的模拟。 |
| [Burst 1.8 文档](https://docs.unity3d.com/Packages/com.unity.burst@1.8/manual/index.html) | 高频扫描使用可编译的数据与 Jobs；不在每个视野源的 MonoBehaviour.Update 中做大量 Raycast。 |
| [Texture2D.SetPixelData](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Texture2D.SetPixelData.html) | 可用原生数组批量传输迷雾显示数据；纹理上传和 Apply 必须单独测量，避免每格托管调用。 |

Valve Developer Community 的 AddFOWViewer 等 API 页面本次访问返回 403，未将未读内容当证据。搜索到的百科、讨论与 Bug Tracker 用作查漏线索，不把玩家报告直接当现行规范。逐英雄技能、道具特例以及准确补丁数值不等同于通用视野系统；需要单独规则表才能声称与指定 Dota 版本一致。

## 通用规则与验收矩阵

以下是按用户确认范围提出的明确实现合同，细节采用项目可配置规则，不声称复刻所有 Dota 英雄特例。

| 模块 | 验收案例 |
| --- | --- |
| 三态 | 初始未探索；进入视野变可见；离开变已探索；当前状态清除但探索记录保留；可切换初始地形已知模式 |
| 阵营隔离 | A/B 可见性和探索历史独立；同阵营来源取并集；观察阵营切换不篡改模拟状态 |
| 多来源 | 重叠区域移除一个源仍可见；最后一个源退出才失去视野；新增/移除/阵营变更不留下幽灵视野 |
| 昼夜 | 每个来源有昼/夜半径；手动切换与自动循环；切换时静止来源也正确重算 |
| 高低地 | 低处不能透视更高平台；高处可看低处；进入高地/返回低地正确更新；显示与逻辑使用同一高度分区 |
| 树木 | 树列遮挡、拐角/窄缝、动态砍树/恢复；变化让受影响视野重算；遮挡在边界与地图边缘安全 |
| 地面/飞行 | 地面受树木/更高地形阻挡，飞行忽略这些遮挡但仍受半径约束；切换不保留旧贡献 |
| 眼 | 侦察眼提供普通视野；真视眼提供侦测；阵营、范围、有效/失效、放置/移除可测试；可配置有限持续时间 |
| 隐身/真视 | 普通敌人需要当前视野；隐身敌人还需要真视。真视覆盖不能单独把黑雾照亮；失去任意条件都隐藏 |
| 临时来源 | 持续时间结束后移除贡献；同区域其他源不能被一起擦除；为未来技能提供显式请求入口 |
| 敌人信息 | 模型、血条/标签、小地图、选中与目标查询遵循同一阵营快照；不能只铺黑色平面但仍允许选中敌人 |
| 记忆 | 移动敌人失去视野后不展示实时位置；可记录最后可见位置/时间作为旧信息。探索历史不等于能看到单位当前状态 |
| 生命周期 | 暂停/重置、反复进入、视野源死亡/移除、资源销毁；Native 容器和纹理释放，不重复订阅 |
| 调试 | 主动切换全知模式应明确标注；正常玩家 HUD 不混入隐藏敌人的实时状态；提供单元测试图和报告导出 |

“本地双阵营”允许本地模拟保留完整数据，玩家可见接口需要过滤；这不是联网防作弊。联网需求未来必须以服务端为权威并过滤同步，不能把本地 Renderer 隐藏宣称为网络数据隔离。

## 推荐数据路径

Authoring/视野预制体 → 配置与运行时源数据 → 遮挡/高度网格 → 来源覆盖计算 → 阵营视野/真视合并与探索历史 → 批量目标显隐判断 → 渲染/HUD/选择接口。

逻辑网格是唯一判定来源，视觉滤波不反向影响规则。来源拥有者、阵营、位置、昼夜范围、地面/飞行、真视范围、到期时间分开记录。移动目标没有视野源时只查网格，不额外做遮挡扫描。

“敌人视野预制体”保存可复用配置与编辑器范围显示；编辑时方便拖放测试。普通敌人仅参与显隐查询，只有指定来源参与遮挡扫描。默认一万目标、两个普通来源；128 个移动来源是额外合成压力档，不是用户要求一万敌人各自贡献视野。

初步选用 CPU 逻辑网格 + Burst/Jobs、批量目标查询、GPU 仅负责显示。考虑阴影投射而非每源对每格发射物理射线。增量方案需要来源贡献可撤销：离开、死亡和半径缩小时不能直接清空同盟仍在覆盖的区域。缓存键包含网格位置、高度、阵营、半径、视野模式和遮挡版本。

## 性能设计与负载分档（建议，非实测）

实现以 128×128 逻辑网格起步，Inspector 可配置到 256，格长与视野半径可配置，视野刷新 10 Hz。画面每帧呈现上次完整快照；逻辑延迟包含最多约 100ms 刷新间隔与 Job 完成时间。未测 256 网格的容量，不从默认成绩外推。

| 档位 | 视野源 / 显隐目标 | 用途 |
| --- | --- | --- |
| 规则图 | 1–16 / 数十 | 遮挡、高低地、真视、阵营组合验证 |
| 常规建议 | 128 / 10000 | 区分少量视野源和万级战斗目标的实际成本 |
| 扩展 | 512、1024 / 10000 | 重叠密集、分散来源、不同遮挡率 |
| 极限 | 10000 / 10000 | 只有用户要求全员提供视野时作为正式目标，不从少源成绩外推 |

半径 R 的单源扫描通常涉及 O(R²) 格，逐格再走整条射线会增加额外距离因子。举例 R=20 格时圆面积约 1257 格，128 个源约 16 万格，10000 个源约 1257 万格/刷新；这是工作量量级估算，不是耗时预测。地图边界、遮挡、缓存命中和移动比例改变实际成本。

不能让多个并行 Job 无同步地写同一阵营位图；采用独立输出后归并、分块写入或有证明的原子策略。稳定场景避免高频分配；不把每源整张地图复制成纹理，不做 GPU 同步回读来供 AI 使用。

验收按固定种子运行静止、全移动、密集重叠、分散、树木批量变化、昼夜切换、来源批量销毁等场景。分别记录遮挡计算、归并、10000 目标查询、纹理上传、主线程等待、完整视野快照延迟及帧耗时 p50/p95/p99、GC 和内存。沿用项目性能文档：独立 Player、预热 10 秒、采样 60 秒、至少 3 次。参考 60 FPS 总帧预算，不预先承诺具体硬件达标。
