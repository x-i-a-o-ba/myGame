# 英雄与技能配置文档

主文件：`英雄与技能配置.xlsx`。当前是从已保存的 Unity 资源整理的设计文档，不是运行时配置源。编辑 Excel 不会自动覆盖 Unity，导入器尚未实现。

## 工作表

- **ID查询**：在黄色输入框填入英雄或技能稳定 ID，返回类型、名称、用途、资源路径。找不到或重复时明确提示。
- **英雄**：每个 HeroDefinition 一行，唯一 ID、名称、属性、用途和资源路径。
- **技能**：每个 SkillDefinition 一行，唯一 ID、瞄准、距离、前后摇、冷却、充能；旧扁平示例单独标明旧模型效果。
- **英雄技能装配**：用英雄 ID 和技能 ID 关联，槽位从 1 开始。QWER 是当前默认输入，不是技能身份。同一技能可被多个英雄引用。
- **技能阶段**：以技能 ID + 阶段序号关联，记录阶段时序、投递、几何及效果顺序。无组合阶段的历史技能不伪造阶段。

## 唯一 ID 约定

沿用配置中的 `stableId`，不另起数字编号，不修改原资源 GUID。新英雄推荐 `hero.<英文标识>`，新技能推荐 `ability.<英文标识>`；统一小写，创建后不因改名修改、不删除后复用。已有 `skill.*` 和随机字符串形式的合法 ID 原样保留。

英雄与技能 ID 全局唯一，检查不区分大小写。显示名称可重复，ID 不可重复；ID 不是 Excel 行号、输入槽或 Unity GUID。装配键为英雄 ID + 槽位序号；阶段键为技能 ID + 阶段序号。

在 Excel 表末尾追加记录，并复制该表已有的检查公式。查询及交叉检查范围为第 6～1005 行（每类最多 1000 条），超过后应扩展引用范围。筛选英雄装配表即可查看其附属技能，Unity 技能设计器的搜索框也支持名称或唯一 ID。

## 当前范围与数据权威

2026-09-24 实际扫描：2 份英雄定义（正式寒冰射手、同英雄换槽示例）、8 个技能定义（4 正式、1 工作台、3 历史）、8 条装配、5 个组合阶段。历史独立被动示例是 PassiveDefinition，不属于当前英雄装配的 SkillDefinition，本表不将它们假装为已装配主动技能。

数值来自已保存资源；Unity 尚未保存的 Inspector 修改不在快照中。表中未使用的默认阶段参数不表示该投递方式会同时消费所有参数。实际执行合同以技能编译器与架构文档为准。

## 更新流程

1. 保存 Unity 配置资源。
2. 自动化入口 `Roguelike.SkillAuthoring.Editor.HeroSkillDocumentation.Export` 只读扫描资源、校验全局 ID 与引用，输出 `Logs/HeroSkillCatalog/source.json`。没有新增菜单。
3. 现有 Excel 已有人手修改时，先备份并按 ID 合并，不直接覆盖。首次生成脚本存放于 `Tools/DocumentationWorkbook/hero-skills-20260924/build.mjs`，重跑会覆盖同名工作簿，仅适用于明确要求重新从 Unity 导出时。
4. Excel 到 Unity 的自动导入、冲突合并及版本迁移尚未实现。

在隔离验证项目导出时，可设置 `HERO_SKILL_SOURCE_PROJECT` 为主项目根目录，只导出主项目实际存在的资源文件，排除隔离检查生成的示例。
