# 技能配置工作台

日期：2026-09-24。状态：**独立技能配置工作台已实现，场景与示例资源已保存，隔离 Unity 6.3 编译、编辑器集成检查和实际界面截图检查完成。** 静态范围工具不执行游戏伤害与 Buff。

## 用户需求与已有事实

用户要求重新创建一个技能配置场景，用于创建技能配置、设计技能与指示器的适配；编辑器内可视化操作，默认范围以 Unity 基本单位为准，编辑成果可以保留并继续使用。此前的组合技能架构、中文编辑器说明及资源命名规则继续有效。

已有实现依据：

- `Assets/Game/Abilities/Core/SkillDefinition.cs` 提供通用技能与 `SkillStage[]`，每段包含目标范围、形状、投递、延迟、重复及效果引用。
- `Assets/Game/Abilities/Core/Execution/SkillTargeting.cs` 提供实际范围几何；圆使用半径，扇形使用长度与半角，直线区域使用长度与半宽。
- `Assets/Game/Abilities/Core/SkillCatalog.cs` 是编译和合法性检查入口。已有阶段与效果应继续通过该入口检查。
- `Assets/Game/Abilities/Core/Execution/AbilityExecution.cs` 从前摇结束的释放时刻分别调度各阶段，保存施法中心与方向；直线弹体的首次碰撞和随后范围结算具有不同参数。
- 本任务开始时 Game 在 `GameCombatController.CastAbility` 中读取首段几何；本轮已将正式技能的 `indicatorColor` 通过编译快照传给 Game 指示器，保留首段瞄准范围规则。
- 历史 `SkillIndicatorDemo` 仅是圆形演示；工作台不能依赖它的独立技能配置来形成另一份战斗范围数据。

架构约束与当前战斗能力见 [组合技能与 Buff 基础架构](ability-foundation.md)。

## 使用流程

菜单和中文面板已在实际 Unity 编辑器中核对；Scene 视图的 Gizmos 开关需保持开启。

1. 从中文菜单打开工作台。若当前场景未保存，按 Unity 的保存提示处理；打开工具不得静默丢弃其他场景修改。
2. 在窗口绑定已有技能，或点击“新建技能”/“复制为新技能”。新建默认为圆形点目标、施法距离 12、半径 3、冷却 4 秒、伤害 10、无资源消耗，附独立伤害效果资源。这些是 AI 选择的起步值，可直接改动；复制继续共享原效果和 Buff。稳定 ID 自动生成，与中文显示名称分开。
3. 在窗口或资源 Inspector 修改参数；在 Scene 视图选择阶段并拖动施法距离、几何范围或参考目标。数字与可视化应同步更新。
4. 在“当前阶段”和“全部阶段”之间切换。当前阶段应清晰可辨；阶段延迟、次数、重复间隔以文字显示，不假装已经实际执行伤害。
5. 执行配置校验。错误应包含技能、阶段或对应资源信息；未完整配置的草稿可以保留，但不能显示为可执行。
6. 需要将技能纳入指定技能库时，显式登记到工作台所绑定的技能库。登记不等于装备到英雄，也不自动改写 Game 的英雄槽位。
7. 点击“保存技能、引用依赖与工作场景”。重新打开工作台后恢复技能引用及参考布局。已启动的 Game 会话仍需按既有规则重开，才能重新编译并读取技能配置。工作台示例资源位于 `Assets/Game/SkillAuthoring/Content`。

在 Project 中选中其他资源后，静态预览仍可显示；重新点击“选中工作台并聚焦 Scene 视图”恢复交互句柄。未选择工作台时不抢占其他对象的编辑操作。创建/复制会生成实际文件，取消保存对话框不创建资源；参数修改、登记和移动锚点支持 Undo，资源文件创建不作为一次可撤销的参数编辑。

复制技能只保证技能定义自身独立。若效果或 Buff 仍指向原资源，修改这些共享资源会影响其他引用者；工具必须把共享关系显示出来，不能将浅复制称为完整独立技能包。

## 单位与几何语义

默认采用 Unity 世界单位；场景提供每格 1 单位的网格和边长 1 单位的立方体作参照。项目既有字段中的“米”采用 1 世界单位对应 1 米的项目约定，不把 Unity 单位描述为引擎强制的物理长度。时间仍为秒，角度为度。

| 参数 | 几何含义 |
| --- | --- |
| 施法距离 | 从施法者到可提交目标点的最大距离；与作用范围半径分别显示。 |
| 圆形半径 | 从作用中心到边界的距离。半径 5 应跨越 5 个单位网格。 |
| 扇形长度、半角 | 长度决定外弧半径；总夹角是半角的两倍。 |
| 直线长度、半宽 | 总宽度是半宽的两倍；不能把总宽直接写入半宽字段。 |
| 直线弹体碰撞半径 | 飞行路径首次碰撞使用的半径，独立于碰撞后的爆炸/区域半径。 |
| 弹体速度 | 单位/秒；静态路径展示不证明飞行时间或碰撞已执行。 |

几何按水平 XZ 世界坐标解释，预览忽略工作台父级缩放的范围倍率。点目标沿用现有距离截断；单位目标保留锚点位置，超距显示中文警告（运行时会拒绝施放）。参考目标重合时以施法者前向作为静态示意；当前 Game 的方向瞄准在零方向时仍拒绝确认。

自身和单体使用对应位置标记；“全体”表示符合目标过滤的全体单位，不以无限大圆假装范围。直线弹的路径走廊与命中区域应区分；示例命中点只用于解释几何，实际首次碰撞位置取决于运行时目标。

## 职责、所有权与生命周期

| 模块 | 所有权及职责 | 生命周期 |
| --- | --- | --- |
| `SkillDefinition` / 效果 / Buff 资源 | 保存共享定义；数值和范围的唯一配置来源。 | 作为项目资产持久保存。 |
| 工作台 Workspace 与锚点 | 保存编辑对象引用、预览阶段和参考布局；不保存冷却、层数、生命等战斗状态。 | 随工作台场景保存和恢复。 |
| EditorWindow / Scene 手柄 | 编辑资源、发出保存/登记/校验操作、显示几何；不结算伤害。 | 窗口关闭释放内嵌 Inspector 与窗口回调；静态 Scene 绘制注册存在于 Editor 域，场景关闭、资源变化、Undo 或域重载清空快照缓存。 |
| 临时校验目录和编译结果 | 收集当前技能及依赖，调用共享编译器；不得替代或覆盖真实技能库。 | 单次校验拥有，成功或异常后都释放临时对象和 Blob。 |
| 正式 `SkillCatalog` | 保存实际登记的定义引用；只有显式登记操作修改。 | 项目资产持久保存；运行会话另行编译。 |
| Game 表现适配 | 消费会话配置快照；本轮接入正式技能颜色，仍使用首段瞄准几何。 | 随 Game 会话建立及重开刷新。 |

预览不能反向写入实际命中结果。打开工作台、选择阶段、刷新视图、脚本重载均不得重置技能资源。范围修改使用 Unity 序列化和 Undo；一次手柄拖动应能整体撤销，Redo 后数字与图形一致。只调整预览锚点或阶段应修改工作台状态，不修改技能数值。

资源保存与场景保存是两个持久化对象。仅保存场景不代表技能资产已写盘；只保存资产不代表参考布局已保存。保存动作须反馈失败，不能在文件未保存时声称保存成功。

## 合法性与能力边界

沿用现有编译器，不创建另一套更宽松的“工作台合法”规则。当前组合技能最多 32 段，每段执行 1–32 次；需要重复时使用正间隔，弹体需要正速度；空效果、非法枚举和悬空引用不能静默通过。效果顺序及 `Source`/选中目标语义继续由共享核心决定。

阶段延迟从前摇结束的释放时刻分别计算，不能解释为上一段结束后再开始下一段。重复查询当前目标，施法中心和方向遵循提交快照。全部阶段叠加用于检查空间配置，不显示虚构的命中集合或时序结果。

本轮工具不运行 ECS 战斗、不执行伤害/Buff、不宣称验证实际弹道碰撞、复杂地形贴合或万敌性能。工作台可检查任意阶段，不代表 Game 已同时显示所有阶段。Excel 导入、完整技能时序播放器、特效编辑器和完整英雄选择流程不属于本轮交付。

## 2026-09-24 第二轮：分类技能设计器与三维抛物线

### 用户方向与团队决定

用户要求三维项目补充抛物线投递，编辑工具成为分类清晰、非程序人员可尝试的独立窗口。主 AI 采用技术代理的共享曲线与 ECS 执行方案、设计代理的分类流程，资源命令由编辑器代理独立实现。以下默认值与范围为 AI 决定，并非用户逐项确认。

### 使用方法

1. 打开 `Tools > Roguelike > 技能设计器`，或双击技能定义资源；无需先打开专用场景。
2. 左侧搜索已有技能，或选择模板并“创建技能资源”：目标点范围伤害、扇形攻击、直线碰撞爆炸、抛物线落点爆炸、自身治疗、单体伤害。
3. 顶部分类页依次为基础信息、瞄准与范围、飞行方式、效果组合、多段与节奏、高级 / 预览。只显示当前方式需要的参数；线形使用完整宽度、扇形使用完整张角，序列化仍保留半宽/半角。
4. 效果页可添加伤害、治疗、减速、眩晕、攻速提升、驱散，或复用已有资源；支持排序、移除引用与制作独立副本。展开共享效果会影响所有引用者；独立化同时复制所引用的 Buff 并生成新 ID。移除引用不删除资源。
5. 阶段支持添加、复制、排序、删除及延迟/重复配置；复制阶段复制数值与数组，效果资源保持共享。至少保留一个正式阶段，避免误入旧兼容模型。各阶段延迟都相对前摇结束的释放时刻，排序不意味着前段完成才开始后段。
6. “打开场景预览”进入既有工作台；选择工作台节点后可拖动范围和抛物线弧高。高级 / 预览页可拖动飞行进度、叠加阶段、登记技能库、单独保存场景。顶部“保存配置”或 Ctrl+S 保存技能与效果/Buff 依赖。

### 三维投递合同

新增 `DeliveryKind.ParabolicProjectile` 追加于旧枚举末尾，不改变旧资产值。SkillStage → SkillCatalog → StageData/SkillAimPreview 保留同一配置；`SkillTrajectory` 同时服务运行轨迹和编辑器采样。

- 默认飞行 1 秒、连线附加弧高 3、发射高度 1、落点高度 0，距离单位为 Unity 世界单位。
- 世界位置为 `lerp(start,end,t) + up * 4 * arcHeight * t * (1-t)`。start/end 已含高度偏移；弧高相对两端连线，不等于世界最高 Y。
- 飞行时间独立于距离；零水平距离仍完成设定时长。绝对模拟时间按原定发射时刻计算，支持延迟、重复和大步长补进度。
- 施放时锁定落点，到达执行一次共享目标查询和效果；中途不碰撞、不会追踪目标；施法者死亡清理飞行。
- 当前瞄准与伤害筛选保持 XZ 地面规则。高度偏移和轨迹是实际三维数据，但不代表已实现球形伤害、地形阻挡或空中单位筛选。
- Scene 轨迹显示真实世界高度和可拖动弧高，进度球只是预览。Game 投射物读取真实位置，抛物线不再加旧展示用的 0.5 高度。

## 2026-09-24：技能前摇与后摇

用户要求新增技能释放前摇（释放时间）和后摇。已在设计器“基础信息 → 施放动作时间”和技能 Inspector 添加秒数配置。默认均为 0，已有资源不修改数值与 GUID。

AI 决定的执行合同：

- 时间线：接受施法 → 前摇 → 正式释放 → 后摇结束。阶段时间为“正式释放时间 + 阶段延迟 + 重复序号 × 间隔”；后摇不等待弹体飞行或多段完成。
- 前摇/后摇期间 Game 禁止移动、发起普攻及再次施放任何技能。移动目标仍可输入，动作锁结束后继续前往；已发射普攻弹体正常结算。输入不排队连放技能。
- 消耗、冷却、充能及普攻蓄层沿用接受施法时提交一次。前摇期间 CastBlocked（禁止施法，如眩晕）取消该次尚未释放阶段，不退款、不返还冷却/层数；取消后立即解除动作锁。
- 已释放技能不会被后续眩晕撤回；死亡沿用清理所有未执行阶段和飞行的既有规则。前摇锁定提交时的目标点与方向，不自动追踪。
- 若同一步跨过释放时间且检测到施法封锁，封锁优先。本项目没有 Buff 生效的亚帧时间戳，明确采用此离散模拟规则。
- Game HUD 当前技能显示前摇/后摇剩余秒数，其余技能显示动作锁定。此轮没有加入角色动作动画或动画事件依赖。

数据流：`SkillDefinition.castTime/recoveryTime` → `SkillData.CastTime/RecoveryTime`。持有者 `AbilityRuntime` 保存 `ReleaseAt/ActionReadyAt/CastSlot/AwaitingRelease`；`AbilityCastTiming` 为动作锁与阶段的共享查询，不混入每帧由 Buff 重算的 Controls。`AbilityExecution` 在通用提交/调度边界执行，不依赖英雄或 QWER。非法负数、非有限数拒绝编译；旧扁平示例不支持这套时序，填写非零值时明确拒绝，避免静默忽略。

弹体统一按释放后的模拟时长推进，避免将前摇所在帧的整段 dt 错算成飞行时间。配置复制、模板、撤销及保存仍走既有序列化路径。技能修改即时用于配置预览，Game 重开会话后读取。场景为静态轨迹工具，没有新增完整技能时间轴播放。
