# AI 制作室：本地群聊工作台

**状态：历史实验原型。**当前约定见 [AGENTS.md](../../AGENTS.md)，AI 自主选择开发工具与协作方式。以下操作仅说明旧看板原型的能力，不作为项目开发限制。

这个工作台把 **Codex 主任务和子代理的可见事件**放在一页：群聊、成员分屏和流程图。你只向主 AI 输入大方向；主 AI 自主拆任务、调用项目角色、核对交付后向你汇报。项目原生可写主任务由 AI 自行验证实现并返工，可按需调用测试角色；你可以选择试玩并反馈体验。

## 启动

在项目根目录打开 PowerShell，运行：

~~~powershell
node Tools/AiTeamDashboard/server.mjs
~~~

在浏览器打开 `http://127.0.0.1:4177`。要求本机已安装 Node.js 24 和已登录的 Codex CLI；本机调查时两者都存在。工作台只监听 `127.0.0.1`，后台由 Node 启动 `codex app-server --stdio`，无需单独的 API key。停止 Node 进程会同时停止它启动的 App Server。若端口被占用，可设置 `PORT` 环境变量后启动。

打开页面后：

1. 在底部输入一个方向，点“交给主 AI”。此时创建新的 Codex 主任务，权限为只读。
2. **群聊**显示你给的方向、主 AI 派工、各角色公开消息和主 AI 汇报。
3. **分屏**同时显示主任务与已派出子代理的独立对话；右栏可逐个展开。
4. **流程图**按实际出现的主/子任务关系与状态绘制，不用预置假数据。
5. “查看已有任务”可输入一个 Codex 主任务 ID，只读加载它和已发现的子代理；“继续告诉主 AI”把反馈发给当前主任务。

项目现已使用 Git；以下工作台限制仅适用于旧原型。这个实验看板新建的任务仍为只读调查与起草，主 AI 只能审查交付范围、文件证据、结论冲突和文档状态，不能声称未实施的功能或未运行的 Unity 检查已经通过。需要代码或资源写入、Unity 编译、Editor/Player 功能检查时，请使用[项目原生 AI 团队流程](../../Docs/ai-team/README.md)：由可写主任务自主决策、实施、验证、返工并向你报告证据；只有真正无法推断或必须由你决定的事项才提问。

## 数据与限制

- 页面上所谓“群聊”是**可见事件的聚合视图**。子代理本身是独立 Codex 任务，并不会自动共享彼此的聊天上下文；主 AI 负责转交需要共享的事实。
- 工作台显示 Codex App Server 可提供的消息、派工事件、状态和工具活动摘要，不显示隐藏推理。子任务实时事件若未被本连接推送，服务会用 `thread/read` 与子任务列表回补；回补可能稍有延迟。历史任务的群聊顺序按可取得的任务时间近似排列，具体上下文以各成员独立对话为准。
- Codex 聊天历史仍由 Codex 保存。工作台只在本机保存最近主任务 ID 与方向，用于重启后重新接入；不要把页面暴露到公网。
- App Server 的相关接口仍标为实验性，Codex 升级后可能需要调整事件适配。数据源、字段与事件依据：[Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server)。Codex 桌面端本身也能展开每个[子代理任务](https://learn.chatgpt.com/docs/agent-configuration/subagents)；本页面增加的是同屏聚合与流程视图。
