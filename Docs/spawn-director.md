# 刷怪导演与软分离

2026-10-24，远征重设计第 2 步。用户授权继续定稿中未完成的内容，并允许适当优化。本步先在单关中替换 30 波，不把三关、营地、词缀和新怪物技能标为已实现。

## 规则与编辑入口

- `Assets/GameData/关卡/刷怪导演.asset`：累计强度时间的目标曲线、0.25 秒补充、4,000 存活硬上限、开局 40% 到 60 秒恢复、潮涌、精英、首领时刻与分离。Inspector 显示中文字段、单位和校验错误。曲线节点间线性插值，末节点以后保持末值。
- `Assets/GameData/关卡/关卡难度曲线.asset`：每分钟复利生命/攻击、线性移速、精英倍率和首领的三关绝对生命/奖励。旧资源 GUID 不变；删除 30 波、整波数量和 `maxPerWave` 字段。
- 两份敌人名册：出场条件改为累计强度时间（秒），六类普通怪依次在 0/45/90/210/150/300 秒开放，抽取权重 55/15/12/6/8/4。尚未开放的权重重新归一化；零权重或未解锁条目不兜底出现。本图专属精英独立标记，供每第 3 个精英和第 1 关首领使用。
- Game、EmberRift 共用导演资源；HUD 显示关卡、目标存活数、首领倒计时、潮涌和狂暴提示。操作、成长、商店和已有技能仍为第 3–7 步之前的版本。

首领本关 210 秒出现，270 秒还活着则攻击翻倍一次；首领期间停止精英、取消尚未生成的潮涌，普通补充目标减半，已有敌人不凭空删除。击杀首领结束本关；本步尚无营地和下一关导航，仍可重开或返回选择。

## AI 补充决策

1. 每批最多生成 128 个，首领、精英、潮涌共用预算；潮涌余量保存在会话中，随后批次继续兑现。卡顿后不补跑多个批次。
2. 普通怪提前为首领预留 1 个名额，首领也不突破 4,000 上限。
3. 生成点从真实相机的地面/模型高度投影并集外再留 3 米，沿环带抽取，70% 偏向英雄实际移动方向。地图边缘先随机重抽，再检查一周方向；绝不把越界位置直接夹回屏幕内。镜头覆盖全地图时暂缓生成，计入位置拒绝次数。
4. 软分离网格默认 1.5 米，按体型取有限半径，每单位每帧最多检查 48 个邻居，速度不超过 2.5 米/秒。完全同点使用成对反向的确定性方向。定身、死亡和正在冲锋的单位不被分离位移；它们仍可作为邻居障碍。拥挤时是软缓解，不保证所有模型绝不重叠，不提供寻路。
5. 第 1 关首领使用现有专属精英原型，保留原有攻击行为。新首领技能、深渊版、精英词缀留给第 5/6 步，不用占位枚举冒充实现。

## 职责与数据所有权

`SpawnDirectorDefinition` / `CombatDifficultyDefinition` / `EnemyRoster` 只保存配置。会话在清空旧局之前校验，复制为 `SpawnDirectorSettings`、`CombatDifficultySettings`、`PopulationPoint` 和 `CombatEnemyKind`。配置资源不保存时钟或随机进度。

`CombatDirectorState` 归会话实体所有，持有本关时间、关卡号、随机种子、补充计时、精英次数、潮涌余量、首领实体与结局。`CombatSpawnDirector` 负责纯数值/抽取/位置决策以及主线程批量实例化；`CombatSimulationSystem` 在死亡回收、经验金币结算之后调用。每种原型一次批量实例化，临时数组在调用内释放。

`GameCombatController` 只把相机投影矩形与实际移动方向写入 `CombatSpawnView`，模拟不访问 Camera。UI 只读导演快照；技能命中与伤害继续使用 `AbilityUnit` 和共享执行核心。

`EnemySeparation` 归模拟系统所有：持久网格随容量增长而复用。每帧敌人行为任务完成后先收集位置，再由另一个 Burst `IJobChunk` 读取网格快照、写各自 Transform；不存在读邻居实时 Transform 的竞态。两个任务的依赖句柄串联，并在串行效果和回收前完成。重开清空实体，下一帧清空网格；World 销毁前完成任务并释放网格。

旧导演脚本由 `CombatWaveDirector` 改为 `CombatSpawnDirector`，保留脚本 `.meta` GUID。旧名册波次字段显式迁为秒，并迁移两份正式资源；旧波次状态不存档，无运行态兼容负担。配置 GUID、怪物 ID、场景引用保持稳定；本项目以外未迁移的自定义名册需要重新设置出场秒数。

## 验证与复现

编辑器入口 `Roguelike.Editor.GameTools.Build` 先执行战斗与开局验证，再构建 Windows 游戏。导演回归覆盖曲线/恢复、严格权重、边缘生成、计时/潮涌/精英/首领、硬上限、失败停止、完全重叠与定身的 Burst 分离。

Player 命令行：

```powershell
./Builds/Game/Game.exe -batchmode --director-smoke --director-output <目录>
./Builds/Game/Game.exe -batchmode --director-smoke --director-map ember --director-output <目录>
./Builds/Game/Game.exe -batchmode --combat-stress --stress-count 4000 --stress-seconds 60 --director-output <目录>
```

压力对照可附加 `--no-separation`；这只影响该次探针会话。压力探针固定种子、让导演实际补充负载、一次性把群体摆进镜头，然后 10 秒预热、持续采样；采样期间怪物自由模拟，英雄补充生命、法力和技能冷却并循环施法。输出逐帧 CSV 与 JSON（帧 P50/P95/P99、模拟 P95、可用时的 GPU 时间、GC、Unity 内存、存活与视锥相交数量、击杀和弹体峰值）。性能结果仅说明该负载，不能代替正常平衡和未实现机制的完整远征验收。

实际结果见 [验证记录](validation-director-2026-10-24.md)。

压力画面使用独立全场相机（正交尺寸 160），游戏刷怪用的相机保持原视野。探针在帧末提交真实 1920×1080 URP 离屏帧，并通过单像素 GPU 读回等待完成，避免隐藏窗口不渲染时得到虚高结果。墙钟包含同步和探针开销，不等于前台呈现 FPS；可见数量是视锥/包围盒测试，不是 GPU 遮挡统计。该渲染器只在显式验证参数下创建，销毁时恢复 Canvas。

`-batchmode` 用于自动化且保留 D3D11，不能添加 `-nographics`。6000.3.18f1 在本机普通窗口模式有无障碍接口退出崩溃，症状与官方 UUM-146676 一致；详见验证记录。没有用强制结束进程或伪造退出码掩盖该问题。
