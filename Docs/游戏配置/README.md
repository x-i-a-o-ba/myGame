# 英雄、技能与怪物配置文档

2026-10-22：技能蓝耗、冷却、基础效果和迁移路径已更新。英雄生命与一级技能蓝耗已同步本轮 30 波版本。成长与完整波次数据见 [当前数值](../wave-balance-and-stat-details.md)，表中未设成长列的项目以 GameData 为准。Excel 保留原有工作表范围；怪物表的 3000 仍是兼容项，完整怪物模板 3001～3008 请查看 GameData/怪物与编号登记。

主文件：`英雄与技能配置.xlsx`。当前是从已保存的 Unity 资源整理的设计文档，不是运行时配置源。编辑 Excel 不会自动覆盖 Unity，导入器尚未实现。

## 工作表

- **ID查询**：在黄色输入框填入数字 ID，例如 `1003`，返回类型、名称、用途、配置来源。支持技能、英雄和怪物；空输入、非整数、越界、缺失和重复均有提示。
- **英雄**：每个 HeroDefinition 一行，唯一 ID、名称、属性、用途和资源路径。
- **技能**：每个 SkillDefinition 一行，唯一 ID、瞄准、距离、前后摇、冷却、充能；旧扁平示例单独标明旧模型效果。
- **怪物**：记录当前普通怪物的数字 ID 与统一战斗参数。配置来源列明确指向当前来源，不能据此认为已经实现多种怪物的独立资源框架。
- **英雄技能装配**：用英雄 ID 和技能 ID 关联，槽位从 1 开始。QWER 是当前默认输入，不是技能身份。同一技能可被多个英雄引用。
- **技能阶段**：以技能 ID + 阶段序号关联，记录阶段时序、投递、几何及效果顺序。无组合阶段的历史技能不伪造阶段。

## 唯一 ID 约定

用户确定数字 ID 起点：技能从 `1000` 开始，英雄从 `2000` 开始，怪物从 `3000` 开始。为避免不同类型重叠，当前实施区间如下：

| 类型 | 当前编号段 | 已有正式配置 |
| --- | --- | --- |
| 技能 | 1000～1999 | 1000 冰霜专注、1001 冰霜扇击、1002 冰霜冲击、1003 冰晶巨箭 |
| 英雄 | 2000～2999 | 2000 寒冰射手、2001 寒冰射手·换槽示例 |
| 怪物 | 3000～3999 | 3000 普通怪物；3001–3008 幽暗荒原怪物、3009–3016 熔火裂谷怪物（2026-10-23，资源在 `Assets/GameData/怪物/`） |
| 装备 | 6000～6999 | 6000 铁剑 … 6017 风暴王冠（18 件，资源在 `Assets/GameData/装备/`，已写入编号登记；Excel 主表尚未加入装备表） |
| 战场 | 7000～7999 | 7001 幽暗荒原、7002 熔火裂谷（2026-10-23，资源在 `Assets/GameData/战场/`，已写入编号登记，分类 `map`；Excel 主表尚未加入战场表） |

上限划分是本轮 AI 的实施决定，不是额外的用户确认。编号段用满时先扩展规则和校验，禁止自动进入其他类型的编号段。ID 必须是数字整数、全局唯一，创建后不随名称变化，删除后不复用。显示名称允许重复；ID 不是 Excel 行号、输入槽或 Unity GUID。

英雄和技能使用 `configId` 作为配表与查找的主键。原字符串 `stableId` 保留为内部兼容标识，不再作为日常配表主键，原资源 GUID 保持不变。主表只显示数字 ID，不混入旧字符串。装配键为英雄数字 ID + 槽位序号；阶段键为技能数字 ID + 阶段序号。

先登记新编号，再在 Excel 表末尾追加记录，并复制该表已有的检查公式。查询及交叉检查范围为第 6～1005 行（每类最多 1000 条）。编号登记文件用于保留已分配编号，删除配置不回收编号。筛选英雄装配表即可查看其附属技能，Unity 技能设计器搜索支持名称和数字 ID。

## 当前范围与数据权威

当前整理范围：2 份英雄定义（正式寒冰射手、同英雄换槽示例）、8 个技能定义（4 正式、1 工作台、3 历史）、1 种当前普通怪物、8 条装配、5 个组合阶段。历史独立被动示例是 PassiveDefinition，不属于当前英雄装配的 SkillDefinition，本表不将它们假装为已装配主动技能。

数值来自已保存资源；Unity 尚未保存的 Inspector 修改不在快照中。表中未使用的默认阶段参数不表示该投递方式会同时消费所有参数。实际执行合同以技能编译器与架构文档为准。

## 更新流程

1. 保存 Unity 配置资源。
2. 自动化入口 `Roguelike.SkillAuthoring.Editor.HeroSkillDocumentation.Export` 只读扫描资源、校验数字 ID 与引用，输出 `Logs/HeroSkillCatalog/source.json`（schemaVersion 2）。没有新增菜单。
3. 现有 Excel 已有人手修改时，先备份并按 ID 合并，不直接覆盖。首次生成脚本存放于 `Tools/DocumentationWorkbook/hero-skills-20260924/build.mjs`，重跑会覆盖同名工作簿，仅适用于明确要求重新从 Unity 导出时。
4. Excel 到 Unity 的自动导入、冲突合并及版本迁移尚未实现。

在隔离验证项目导出时，可设置 `HERO_SKILL_SOURCE_PROJECT` 为主项目根目录，只导出主项目实际存在的资源文件，排除隔离检查生成的示例。
