# Codex 单主 AI 游戏开发工作流

状态：2026-10-07 起为本项目的当前工作流。用户在 `D:\UnityProject\myGame` 的 Codex Local 任务中给出目标，当前主 AI 自主完成设计、实现、验证和汇报。旧 [AI 团队方案](ai-team/README.md)只作历史记录。

## 技能来源与取舍

采用 [Matt Pocock 的 Skills](https://github.com/mattpocock/skills) 中“小而可组合”的工程方法，固定来源提交 `6fd947921b935b7e1e69293a200400f0fdd5c15f`，项目本地安装：

| 技能 | 使用时机 | 本项目的边界 |
| --- | --- | --- |
| [`codebase-design`](../.agents/skills/codebase-design/SKILL.md) | 设计或改造代码模块的接口、职责与测试接缝 | 以现有 Unity/ECS 约束和 `Docs/ability-foundation.md` 为准；由当前 AI 完成方案比较 |
| [`writing-for-agents`](../.agents/skills/writing-for-agents/SKILL.md) | 修改 `AGENTS.md`、Skill 或供 AI 阅读的操作文档 | 精简常驻规则，按需链接详细项目文档 |
| [`unity-requirements-first`](../Tools/Skills/unity-requirements-first/SKILL.md) | 开发 Unity 功能、架构、渲染和性能方案 | 项目专有规则；当前主 AI 自主补齐普通细节并负责验证 |

原有同名全局 Unity Skill 副本未同步；在本项目内以 `Tools/Skills/unity-requirements-first/SKILL.md` 和 `AGENTS.md` 为准。

这些是提示词技能，不是后台常驻进程，也不会自行运行 Unity。原仓库的 `implement-spec` 和 `code-review` 依赖子代理；`implement` 要求 Git 提交；`setup-matt-pocock-skills`、`to-spec`、`tdd` 等默认引入工单或额外用户确认。项目于 2026-10-21 启用 Git；用户明确要求一个 AI 自动推进，仍不将这些技能设为当前流程。原版技能只在上述两个适用场景中使用，项目规则和用户当次指令优先。

## 每次任务怎样执行

1. **核对事实。**读取 `AGENTS.md`、相关需求和架构文档，再看实际代码、场景、资源和 Unity 包版本。技能/Buff 工作先读 `Docs/ability-foundation.md`。指出文档与现状的差异。
2. **定可执行目标。**把用户方向具体化为玩家可观察的行为、触发与输入、边界、默认数值及适用的验证场景。将用户确认、检查事实、AI 决定和未验证项分开。普通未知项由主 AI 决定；真正需要用户决定的边界遵循 `AGENTS.md`。
3. **实现完整切片。**先查已有共享模块，再依依赖顺序修改代码、场景、Prefab、配置与资源。大改动可以在当前聊天里分步实施；不创建子代理或独立任务。场景、Prefab、Packages、ProjectSettings 等改动前检查 Git 工作区与提交状态，保留可恢复副本或已提交版本，并检查引用；保留用户未提交改动。
4. **运行适用反馈。**代码修改至少做针对性的静态检查；能运行时做 Unity 编译，并按风险执行 Editor、Player、游戏行为或性能测量。配置和 Inspector 修改要在实际 Editor 中检查。发现问题修复后复验；环境阻塞时写明已做的替代检查和残留风险。只改文档或工作流时，无须为此启动 Unity。
5. **自行审查并汇报。**主 AI 核对交付范围、文件事实、兼容与资源引用、文档状态、实际运行证据。向用户简洁说明完成了什么、重要规则和数值为何这样定、未知项怎样解决、验证结果与未完成限制。

只有目标无法可靠推断、会违反用户明确约束，或涉及不可逆的数据损失、外部发布/付费等事项，才集中向用户提问。已有授权继续有效。没有运行的检查标记“未验证”；性能目标和 Player 实测结果分开。

## 性价比与后续改进

这套上游技能采用 MIT 许可，项目只保存两个文本技能及许可证，没有额外运行服务。Skill 会增加少量上下文和维护成本；它们改进的是设计与文档判断，本身不保证功能正确。对当前项目，选择性安装比全套接入工单、Git 和多代理流程更省操作；节约多少 token 或开发时间尚无本项目实测，不能写成量化收益。

后续最有价值的改进是为常做的 Unity 行为建立可由主 AI 重复执行的编译、Editor、Player 检查入口，并记录失败时的日志路径。启用 Git 后仍按任务需要评估依赖分支和提交的技能；用 Git 提交、任务前备份及变更记录保证可恢复性。只有术语反复引起实现歧义时再建立游戏领域词汇表，避免额外文档负担。

## 怎么使用

打开 Codex 中的 `myGame` 项目，使用 Local 任务，直接描述目标，例如：“在 Game 场景加入一种冰系敌人，按项目规则自行决定技能与数值，完成实现、适用验证并汇报。”当前主 AI 会在同一聊天完成工作。安装的技能位于项目 `.agents/skills`；Codex 通常自动发现改动，若技能列表未刷新，重开该项目任务或 Codex。

该仓库没有被整体安装，也不会自动更新。未来要新增技能，先核对它是否要求反复追问、工单、Git、子代理，以及是否支持 Unity 的真实验证；只复制需要的技能并记录来源版本和许可证。
