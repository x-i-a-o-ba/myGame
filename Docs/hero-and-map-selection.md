# 开局选择英雄与战场

更新：2026-10-23。用户要求：实现选择角色功能的场景，选择完后再选择游戏场景；游戏场景再设计一个，每个游戏场景有不同的怪物。界面布局、按键、返回流程、第二战场“熔火裂谷”的主题和 8 种怪物的数值由 AI 决定。

> 状态：代码、场景、面板和配置已经写完，**没有在 Unity 中编译、打开或运行**（本轮开发环境没有 Unity），只做了 C# 语法检查和不依赖 Unity 的语义检查。场景与面板 YAML 是手写或脚本生成的。待验证清单见 [验证记录](validation-hero-map-selection-2026-10-23.md)。

## 玩家流程

主菜单 → 选择英雄 → 选择战场 → 战斗 → 返回选择（或回主菜单）。

| 步骤 | 场景 | 界面与操作 |
| --- | --- | --- |
| 主菜单 | Main | “开始游戏”进入选择场景（原来直接进入 Game）。 |
| 第 1 步：选择英雄 | SelectScene | 左侧是英雄卡（头像、名称、定位）。中间的 3D 展示台缓慢旋转所选英雄的模型。右侧是详情：头像、名称、定位、简介，6 项基础属性（生命、法力、攻击、攻击间隔、攻击距离、移速），普攻和 Q/W/E/R 技能（图标、名称、类型、冷却/法力、简述）。点击英雄卡或按 ← → 切换；点击“下一步：选择战场”或按 Enter 进入第 2 步；点击“返回主菜单”或按 Esc 回主菜单。 |
| 第 2 步：选择战场 | SelectScene | 战场卡显示预览图、名称、简介、“共 N 波 · N 种怪物 · N 种首领”，以及最多 8 个怪物的头像、名称和标签（开局出现 / 第 N 波起 / 精英 / 首领）。点击卡片或按 ← → 切换；点击“开始战斗”或按 Enter 进入战场；点击“上一步”或按 Esc 回第 1 步，已选的英雄保留。 |
| 战斗 | Game（幽暗荒原）或 EmberRift（熔火裂谷） | 使用所选英雄，以及所选战场的敌人名册和难度曲线；右上角显示战场名称。F5 重开时英雄和战场不变。 |
| 返回选择 | — | 第一次点击右上角“返回选择”，按钮变成“确认返回？”；3 秒内再点一次才离开，超时自动取消，防止误触。死亡或通关结算面板上的“返回选择”会立即返回。回到选择场景时，默认选中上一局的英雄和战场。 |

直接在 Editor 中打开某个战场场景运行时，没有开局选择，沿用场景上的英雄和战场配置，方便单独调试战场。

原 Game 右上角的英雄切换按钮（`HeroRoster`）已删除，英雄只在选择场景中选择。

### 新增一个英雄

1. 按现有方式制作 `HeroDefinition`（技能、普攻、成长、头像），填写“定位标签”和“英雄简介”，可选填写“英雄展示预制体”。
2. 在开局选择目录的英雄列表中添加它（最多 4 个）。
3. 运行 `Tools/Roguelike/维护/检查开局选择流程`。

### 新增一个战场

1. 复制 `EmberRift.unity`（或 Game.unity），修改地面、装饰与灯光；场景中的 `GameCombatController` 保持唯一。
2. 新建敌人名册，并把新战场的怪物预制体加入名册（新增怪物见 [敌人说明](enemies-and-controls.md) 3.5 节）。新怪物不要与其他战场重复，否则流程校验会报错。
3. `Create > Roguelike > 战斗 > 战场定义`，命名为 `7xxx_中文名称`，领取 7000–7999 的数字 ID 并登记到 `Docs/游戏配置/编号登记.json`；填写名称、简介、预览图、场景 ID、名册和难度曲线。
4. 在资源清单 `Assets/Resources/ProjectResourceCatalog.json` 中添加 `Scene.<场景名>`（或把场景加入 `SceneFrameworkMigration.Scenes` 后运行 `Tools/Roguelike/维护/更新资源目录`），再加入 Build Settings 和 `GameTools.BuildScenes`；场景内 `GameCombatController` 的“战场”指向新战场定义，Canvas 上的 `SceneNavigation` 保留 `game.leave` / `game.select` 两条路由。
5. 把新战场加入开局选择目录（最多 3 个），运行流程校验。

## 结构与边界

- `StartSelectionCatalog`、`GameMapDefinition` 是只存配置的 ScriptableObject，不保存运行状态。
- `GameSelection` 是本次运行的内存选择（英雄、战场），选择场景确认时写入，战场开局时读取；不写存档，进入播放模式时清空。
- `SelectSceneController` 只读取目录、通过场景 `UIManager` 发布展示键，并处理 `select.hero/map/next/back/start` 命令；`select.menu` 由 `SceneNavigation` 处理。面板不引用控制器。`HeroShowcase` 只负责外形。
- `GameCombatController.map` 指定本场景的战场定义。开局时 `ApplySelection` 总是换成所选英雄；只有所选战场的场景就是当前场景时才替换战场，否则保留场景配置并输出警告。生效的名册和难度为：战场定义优先，其次控制器原来的字段。
- `SceneNavigation` 改为路由表：同一命令只出现一次；确认时间大于 0 时，第一次点击只发布显隐键 `<命令>.confirm`，在确认时间内再次点击才执行（使用不受暂停影响的真实时间）。Main 的 `main.start` 改为进入 `Scene.SelectScene`。
- Windows 构建包含 Main、SelectScene、Game、EmberRift，Main 是首场景。`GameStartupRouter` 让 `--game-smoke` / `--game-balance`（未指定 `--start-scene`）直接进入 Game，原有整局验证命令不变。
- 场景导航、选择控制器、英雄展示台、战场定义、开局选择目录、战斗控制器和战斗探针都有中文 Inspector，大多直接在 Inspector 中显示校验结果。
