# 刷怪导演与软分离验证

日期：2026-10-24。对应远征第 2 步，单关接入 Game 和 EmberRift。规则、AI 取舍、职责与迁移见 [刷怪导演](spawn-director.md)。

## 构建与功能

Unity 6000.3.18f1、URP 17.3.0、Entities 1.4.8；Windows x64 Release Player，Direct3D11。`Roguelike.Editor.GameTools.Build` 运行实际编译库/ECS 检查和场景装配检查后构建游戏。最终结果与日志见下方证据表。

新增回归包含：目标曲线插值、开局恢复、跨关强度时间、首领补充减半、非法配置、严格权重与解锁、512 个镜头外位置、地图角落和全地图可见时的位置拒绝、批次上限、精英独立计时、每第三只专属精英、潮涌分批、首领时刻与硬上限、失败停止、完全同点的反向分离、实际 Burst 任务与定身不位移。

Player 导演探针在两张正式战场验证初始化、镜头外生成、暂停、90 秒精英、150 秒潮涌、真实画面、210 秒首领与 6,000 生命、停止精英/潮涌、270 秒攻击翻倍且只触发一次、击杀本关首领、胜负停止生成和重开清理。探针跳转导演时钟，不等于人工连续玩满 4.5 分钟。

## 压力测量口径

- 本机 Ryzen 7 7745HX、RTX 4060 Laptop 8GB、32GB RAM、Windows 11 26200；不代表最低配置。
- 每轮独立 `-batchmode` Player（不使用 `-nographics`，仍是 D3D11/真实 GPU），固定导演种子 `20261024`，目标存活 4,000、10 秒预热、60 秒采样，测试期间不开 Unity Editor，不并行跑其他 Player。
- 实际导演先填满，初始群体仅搬运一次到中央；随后正常移动、攻击、弹体、共享技能命中/伤害、死亡回收与补充。英雄补充生命/法力并循环释放已学习技能，故不是正常玩家伤害平衡测试。帧时序和 Job 排序不保证逐帧重放一致。
- 游戏相机仍用于镜头外补怪；额外正交尺寸 160 的全场相机逐帧提交 1920×1080 URP 离屏渲染，包含实际模型和 HUD。每帧等待单像素 GPU 读回，墙钟计入同步、探针记录和原游戏帧，不是前台呈现 FPS。全场视角下模型屏幕尺寸更小，不代表普通镜头的像素填充负载。
- 采样逐帧记录存活量，视锥与包围盒相交数量每 0.5 秒刷新一次；后者不含 GPU 遮挡统计，不能声称每帧 4,000 个模型都完整可见。峰值达到 4,000，击杀后的瞬时缺口由 0.25 秒批次填补。
- `simulation_ms` 是整个战斗系统（含 Job 等待）耗时；不是分离任务单独耗时。GPU 专用计时在当前构建返回 0，视为不可用。Release Mono 的主线程分配计数始终返回 0，最终报告将有效标记设为 false、汇总设为 -1；不可据此宣称零 GC。Unity 内存为分配总量采样峰值，不是进程 RSS。

帧末提交遵循 [Unity 6.3 URP 渲染请求示例](https://docs.unity3d.com/6000.3/Documentation/Manual/urp/User-Render-Requests.html)；早期 Update 阶段提交曾出现原生渲染崩溃，移到帧末后重新构建并完成重复验证。不把早期崩溃批次当作通过数据。

## 调试中发现并修正

1. 角落生成随机重试可能全部失败，增加一周均匀方向兜底，仍拒绝镜头内位置。
2. 在辅助类中调度 `IJobEntity` 未被源生成替换；改为显式 `IJobChunk` 和组件句柄，实际 Burst 分离检查通过。
3. 暂停探针在设置 `Time.timeScale` 的同一帧断言，误把下一帧生效当失败；等待时间状态生效再比较，模拟自身也在零 dt 时返回。
4. 旧战斗探针假设 3 秒内遇敌，镜头外生成后不成立；改为攻击移动到实际最近敌人，限定 15 秒等待，并仍要求真实发射与命中。
5. 后台直接截屏产生黑图且帧率虚高，初轮结果废弃。改为帧末显式真实渲染、GPU 完成等待和图片非空检查；重复提交早期阶段的崩溃结果同样废弃。
6. GC 计数接口不支持却返回零；最终探针明确标记不可用，早期 `stress-1` 与 `render-baseline-verified` 的 GC 字段不用于结论。

7. 未使用的 `com.unity.2d.animation@13.0.5` 启动时创建 fallback ComputeBuffer，场景没有 SpriteSkin 使用路径，退出留下回收警告。扫描全部场景/Prefab/配置脚本 GUID 与代码，确认没有该包的引用。将 `com.unity.feature.2d` 展开为其余 8 个原版本依赖，只移除 2D Animation，Package Manager 更新锁文件。该警告随后消失；这与下述无障碍退出异常是两个问题。

## 边界

本步没有三关/营地、深渊变体、精英词缀或新首领技能，仍保留旧操作、成长与商店。通过本机 4,000 目标负载检查不代表 8,000–10,000、最终远征完整战斗、最低配置、长时稳定性或人工手感达标。软分离限制邻居检查与最大速度，解决重叠趋势，不是刚体碰撞或寻路。

**窗口模式退出尚有引擎限制：** 功能断言全部成功后，6000.3.18f1 窗口模式 Player 在本机退出时报 `0xC0000005`。用随安装提供的 PDB 解析 Windows 事件中的 `UnityPlayer.dll + 0xB1CBD1`，定位到 `RuntimeStatic<PlatformAccessibilityManager,0>::StaticDestroy + 0x51`。与 Unity 官方 [6000.3.21f1 发布说明](https://unity.com/releases/editor/whats-new/6000.3.21f1) 中 UUM-146676（Windows Player 与 UI Automation 客户端交互后退出崩溃）的描述一致，因此判断为当前引擎版本问题，尚未在本项目升级后验证。最终自动化采用 `-batchmode` 绕开窗口退出路径并记录真实退出码，不能把它当作普通窗口退出也已修复。项目 Editor 版本未改变，也没有关闭用户系统的无障碍服务。
